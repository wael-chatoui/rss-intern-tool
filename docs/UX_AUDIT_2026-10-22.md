## Défaut corrigé

**P1 : la fermeture des inscriptions pouvait masquer la connexion des membres existants.**

Scénario reproduit avec un membre fictif dans une base SQLite temporaire, sans
propriétaire activé et avec inscriptions et paiements fermés : la vraie API de
connexion acceptait ses identifiants (HTTP 200), mais `/connexion` ne présentait
aucun champ et affichait « L’accès reste à configurer ». La page utilisait seulement
l’existence du propriétaire et le drapeau d’ouverture des inscriptions.

La page tient désormais aussi compte de l’existence d’un document de compte abonné.
La requête serveur renvoie un booléen agrégé avec `SELECT 1 ... LIMIT 1`, sans lire
de contenu éditorial, sans rechercher une adresse e-mail et sans transmettre de
compte au navigateur. Les index d’adresses et les espaces éditoriaux ne suffisent
pas à déclarer un compte existant. Une installation entièrement vide conserve les
instructions d’activation. Les règles de mot de passe, session, origine et droits
d’abonnement restent celles déjà en place.

  isolé : compilation, contrôles de types, génération des pages et traces
  terminés avec le code de sortie **0**. Aucun contrôle de sécurité contourné.

## Icône native, correctif distinct

`src/app/icon.svg` reprend uniquement le monogramme `r.`, le vert `#285b45`,
le blanc, les angles de 5 pixels et la pile serif Newsreader/Georgia du logo
existant. Le fichier de 299 octets ne contient ni script ni image intégrée,
ni lien ou chargement de police externe. Aucun logo ou thème nouveau n’est créé.

La convention `app/icon.svg` a été vérifiée dans le code installé de Next 15.5.28.
Un unique build de ce correctif termine avec **exit 0** et expose `/icon.svg`
comme route statique. Sur le serveur compilé local et isolé, `/`, `/demo` et
`/connexion` répondent HTTP 200 et déclarent toutes l’icône avec
`rel="icon"`, `type="image/svg+xml"` et `sizes="any"`. Leur URL contient le même
hash de contenu. Chaque requête de cette URL répond HTTP 200, avec le bon type
MIME et un contenu identique au fichier SVG source.

Le rendu local Sharp/libvips du SVG à 16 et 32 pixels a été inspecté : le `r.`
reste reconnaissable, le point visible et aucun caractère n’est coupé. Les
petites images de contrôle restent privées, hors dépôt ; le seul asset livré
est vectoriel. ImageMagick n’a pas résolu la pile de polices, son rendu n’est
donc pas présenté comme une preuve. Le rendu dépend de la police serif
disponible localement ; le SVG n’embarque pas Newsreader.

Limites : aucun navigateur ni service externe ouvert, aucun essai Safari,
écran d’accueil mobile ou client ancien. L’ancienne URL `/favicon.ico` reste
HTTP 404 : aucun faux fichier ICO ni repli binaire n’est ajouté. Les clients
compatibles SVG utilisent l’icône explicitement déclarée. Le serveur de recette
a été arrêté après les vérifications. Le reçu HTTP privé est conservé dans
`Codex/recovery/la-redaction/favicon-http-proof.json`.
